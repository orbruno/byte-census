# ADR-002 Compliance Matrix

Author: Orlando Bruno
Contract version: 1.0.0
Satisfies: WI-CONTRACTS AC-10

Baseline: ADR-002, "LLM and Agent-Friendly Design Baseline", of the CLI Creation playbook (private document, cited by name). Scope: the `byte-census` commands. The legacy `dupfind` adapter is assessed separately at the end.

Status: `met`, `adapted` (purpose met with a stated difference), or `not applicable`.

## Output

| # | Requirement | Status | Rationale |
|---|---|---|---|
| O-01 | stdout carries structured data only | adapted | JSON is the default format. `--format table` is an explicit opt-in for people; agents never receive a table unless they ask for it. |
| O-02 | stderr carries diagnostics and errors as JSON | met | Errors are one JSON object on stderr ([envelope.md](envelope.md#error-object)). byte-census writes no progress output. |
| O-03 | No ANSI, spinners, or borders when stdout is not a TTY | met | WI-CORE AC-06. |
| O-04 | `NO_COLOR` respected | met | WI-CORE AC-06. |
| O-05 | `--page-all` NDJSON for paginated results | not applicable | No command returns paginated resources; each returns one complete document. Display size is bounded with `--top` after complete totals. |
| O-06 | JSON structure stable; breaking changes need a major version | met | `meta.schema_version` and the version policy in [envelope.md](envelope.md#schema-version-policy). |
| Table and CSV output | Formats beyond JSON | adapted | Table is opt-in (`--format table`). CSV exists only in the legacy `dupfind`; byte-census output is nested and does not fit CSV. |
| `--output` | Standard flag name for file output | adapted | byte-census has no `--output`; users redirect stdout, which keeps the package free of write calls (WI-SAFETY guard). `dupfind --output` remains and creates files exclusively, exiting 3 if the target exists or is a symlink; there is no `--force`. |

## Control

| # | Requirement | Status | Rationale |
|---|---|---|---|
| C-01 | Exit 0 on success, non-zero on failure | met | Partial coverage is still success and is reported in `meta.status`. |
| C-02 | Semantic exit codes 2, 3, 4+ | met | 0, 1, 2, 3, 4 as defined in [envelope.md](envelope.md#exit-codes). |
| C-03 | `--dry-run` on mutating commands | not applicable | Nothing is ever mutated. Every command is already a preview; suggestions are text and never executed. |
| C-04 | `--yes` or `--force` on irreversible mutations | not applicable | No mutation exists. Every suggestion carries `requires_owner_authorization: true` for the person who might run it. |
| C-05 | No interactive prompts; every input has a flag | met | The CLI never reads stdin or prompts (WI-CORE AC-07). A macOS privacy consent dialog can be raised by the operating system; it is outside the CLI's control and a denial is recorded in `incomplete_coverage` ([quantities.md](quantities.md#incomplete-coverage)). |

## Discoverability

| # | Requirement | Status | Rationale |
|---|---|---|---|
| D-01 | Help generated by the framework | adapted | Click generates help, since the implementation is Python (WI-ADR-PYTHON) rather than Rust with Clap. |
| D-02 | Help starts with `Usage:` and an example | met | Every command's help starts with `Usage:` and includes an `Example:` block (DOD-06). |
| D-03 | `-h` short help, `--help` full help | adapted | `-h` and `--help` both print the same help; Click has no short form, and the help is already compact. Both are covered by help snapshot tests. |
| D-04 | Help on bare invocation when arguments are required | adapted | Bare `byte-census` and each command group print help and exit 0. A leaf command missing a required argument exits 2 with a JSON error whose `help` field names the `--help` command, keeping stderr machine-readable. |
| D-05 | `schema` subcommand | not applicable | The command surface is static. Schemas are documented in `docs/contracts/` with versioned examples. |
| Naming | Full words; `noun verb`; kebab-case flags; snake_case keys | met | `docker scan`, `caches scan`, `artifacts scan`, `duplicates scan`, `disk map` (`map` is the verb; help states it is the one command without `scan`, WI-AGENT-DOCS AC-02); flags such as `--scan-root`, `--large-file-min`, `--min-size`; snake_case keys. |

## Safety

| # | Requirement | Status | Rationale |
|---|---|---|---|
| S-01 | Path validation: traversal, null bytes, outside allowed roots | adapted | Null bytes and control characters exit 3. Paths are canonicalized rather than rejected for `..`. Declared scan roots are unrestricted (any readable directory) because every operation is read-only; `disk map` alone requires the data volume. |
| S-02 | Control characters rejected in string inputs | met | Exit 3 (WI-SAFETY AC-06). |
| S-03 | Resource IDs validated | not applicable | No command accepts a resource ID. Choice options (`--format`) are validated by Click. |
| S-04 | Error anatomy: what, why, how to fix, where to get help | met | `error`, `reason`, `suggestion`, `help`. |
| S-05 | User strings never executed as shell commands | met | `shell=False`, exact argv allowlist, and no suggestion or user value reaches the runner ([argv-allowlist.md](argv-allowlist.md)). |
| Parse errors | Parse errors as JSON | met | Click usage errors are converted to the error object with exit 2 (WI-CORE AC-04). |
| Noninteractive | Runs unattended | met | No prompts, no stdin, timeouts on every subprocess. |

## Legacy `dupfind`

| Requirement | Status | Rationale |
|---|---|---|
| Whole baseline | adapted | `dupfind` is a frozen v1 adapter kept for its existing consumer until 3.0.0. It keeps table as its default, v1 JSON and CSV, and Click's text errors, so its consumer does not break. Changes are limited to help text (`Usage:` and `Example:` for DOD-06), a stderr deprecation notice, and exclusive `--output` creation (exit 3). See [legacy-exit-codes.md](legacy-exit-codes.md). |
